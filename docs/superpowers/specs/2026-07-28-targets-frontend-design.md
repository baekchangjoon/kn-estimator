# targets 범용 앞단 설계 (--targets / --n + 공통 이상치 감지)

> 상태: 3-벤더 리뷰 반영 완료 (2026-07-28; Claude sonnet ×2 + Gemini 3.5 Flash —
> Cursor 슬롯은 키체인 잠금으로 Sonnet 폴백. 22건 전 건 수용, §12)
> 관련: docs/CALIBRATION.md §6 (범용화 로드맵 — 본 설계가 이를 구현·대체),
> docs/superpowers/plans/2026-07-28-kiro2kn-adapter-plan.md D10 (--label 범용화)

## 1. 배경과 목표

kn-estimator의 추정 파이프라인은 두 부분으로 나뉜다.

- **앞단(front-end)**: 대상 목록을 만들고 각 대상의 작업량 w를 추정하는 부분.
  현재는 Spring 스캐너(`scan.py`/`endpoints.py`) 하나뿐이다 — JSON 엔드포인트를
  열거하고 DI 그래프를 추적해 w를 계산한다.
- **뒷단(back-end)**: 캘리브레이션 셀 `<label>/<model>`의 계수로 K*·벽 제약·
  bin-packing·비용을 계산하는 부분(`plan.py`/`model.py`). **단위 의미를 전혀
  모른다** — N(개수), w(상대 크기), group(묶음 힌트)만 소비한다.

`--label` 범용화(PR #16)로 셀 축은 자유로워졌지만, 대상 목록의 공급원이 Spring
스캐너뿐이라 "100개 클래스 분석", "문서 200건 번역" 같은 임의 반복 작업에는 여전히
쓸 수 없다. 본 설계는 **범용 앞단**을 추가한다:

1. `--targets <파일|->`: 사용자가 만든 대상 목록(텍스트/JSON)을 직접 공급.
2. `--n <개수>`: 목록 없이 개수만 (균일 w 가정) — 최소형.
3. **공통 이상치 감지**: 어느 앞단이든, w가 이질적으로 큰 대상을 감지해
   경고·권고를 낸다. Spring 경로도 같이 혜택을 본다.

뒷단은 수정하지 않는다(그루핑 수학 불변). 함께 초급 엔지니어용 개념 문서
`docs/CONCEPTS.md`를 신설한다.

## 2. 용어

| 용어 | 정의 |
|---|---|
| 대상(target) | 반복 작업이 적용되는 단위 하나 (엔드포인트·클래스·파일·티켓… — 의미는 사용자만 안다) |
| w | 대상 하나가 세션에 끌고 들어올 리소스의 **상대** 크기. 스케일 불변(일괄 배수 무영향) |
| group | 같은 세션에 묶으면 유리하다는 힌트 (스캐너 경로에선 컨트롤러) |
| 슬라이스 | 앞단이 뒷단에 넘기는 내부 표현: `{"endpoint": {...}, "w_tokens", "unresolved", "external_call"}` |
| 단위 일관성 계약 | 파일럿 원장의 n과 추정의 N은 **같은 단위**로 세어져야 한다 — 툴이 검증 불가, 사용자 책임 |

## 3. CLI 계약

```
kn-estimate <project_root>                # 기존: Spring 스캐너 앞단
kn-estimate --targets <파일|->            # 신규: 대상 목록 앞단 (- = stdin)
kn-estimate --n <개수>                    # 신규: 개수만 (균일 w)
```

- **정확히 하나의 소스**만 허용한다. `project_root`(위치 인자)를 `nargs="?"`로
  바꾸고, 소스 0개 또는 2개 이상이면 한국어 SystemExit (조용한 우선순위 없음 —
  어느 입력이 무시됐는지 모르는 상태를 만들지 않는다).
- **범용 소스에서는 스캐너 로직을 완전히 우회한다**: `scan.inventory`/
  `scan.build_slices`를 호출하지 않고, `args.project_root`를 참조하는 모든 지점
  (root 존재 검사 cli.py:164-166, 스캔 cli.py:174/177, `대상:` 줄 cli.py:240,
  out-dir 기준 cli.py:223, `--groups` 헤더 cli.py:305)을 소스별로 가드한다 —
  `project_root=None`인 채 `Path(None)`에 도달하는 TypeError 경로를 남기지 않는다.
- `--n`은 양의 정수만. `--targets` **파일 부재**·빈 목록은 SystemExit.
- 기존 옵션(`--label/--model/--calibration/--w-soft/--w-hard/--conservative/`
  `--parallel/--groups/--out-dir`)은 세 소스 모두에서 동일하게 동작한다.
- `--out-dir` 기준 경로: 스캐너 소스는 기존대로 `project_root` 기준,
  `--targets`/`--n` 소스는 **cwd 기준** (프로젝트 루트가 없으므로).
- `--groups` 출력의 `[헤더]`는 스캐너 소스에선 기존대로 프로젝트 디렉터리명,
  범용 소스에선 §7의 소스 라벨(목록 파일 stem·`stdin`·`--n N`)을 쓴다.

## 4. 입력 형식 (`--targets`)

### 4.1 텍스트 목록 (기본) — 한 줄에 대상 하나

```
find src -name '*Service.java' > targets.txt
kn-estimate --targets targets.txt --label analyze --model sonnet
ls docs/*.md | kn-estimate --targets - --label translate --model haiku
```

- **줄 정규화**: 각 줄은 `\r\n` 제거 후 앞뒤 공백을 strip한 문자열이 id다.
  빈 줄·`#` 시작 줄은 무시. 경로에 공백이 포함돼도 한 줄이 통째로 id이므로 문제
  없다 (셸 인용은 목록 생성 시점의 사용자 몫).
- **중복 id는 SystemExit** (같은 대상을 두 번 세면 N이 부풀어 비용이 과대추정된다
  — 조용한 dedup 금지). 판정: strip된 id가 실존 파일이면 `Path.resolve()` 정규화
  후 비교(`./a.txt`와 `a.txt`, 절대/상대 혼용을 잡는다), 아니면 리터럴 비교.
  한계: 비경로 문자열이 다른 표기로 같은 대상을 가리키는 경우는 감지 불가 —
  §2 단위 일관성 계약과 같은 사용자 책임으로 문서화한다.
- **w 자동 추정**: 모든 줄이 실존하는 **일반 파일**(`is_file()`; 디렉터리 제외)
  경로(cwd 기준 또는 절대)이면 `w_tokens = max(1, 파일크기 bytes / 4)`
  (스캐너와 동일 근사; 0바이트 파일의 w=0이 w_mean 0 나눗셈·0가중 슬라이스를
  만드는 것을 1로 클램프해 차단. `is_file()` 통과 후 크기 조회의 OSError는
  TOCTOU 레이스이므로 크래시 대신 w=1 폴백 — `scan.tokens_of`와 같은 관용),
  `group = str(Path(id).parent)` (입력 표기
  기준 부모 디렉터리 문자열 — cwd 상대화를 시도하지 않으므로 cwd 밖 절대 경로에서
  `relative_to` ValueError가 없다).
- **일부만 일반 파일이면**: 자동 w를 포기하고 **전체 균일 w + 전체 무그룹**으로
  폴백(부분 그룹은 배치 왜곡) + stderr 경고. 문구는 미실존과 디렉터리를 구분한다:
  "N건 중 M건이 일반 파일이 아니라(미실존 K건, 디렉터리 L건) w를 균일 가정합니다"
  + 해당 예시 최대 5건. 섞어 재면(실존=크기, 그 외=1) 상대 비교가 왜곡되므로
  all-or-nothing.
- 일반 파일이 하나도 없으면(이름 문자열 목록): 균일 w, 무그룹. 경고 없음 — 정상
  사용이다. 리포트에 "w: 균일 가정(목록에 파일 경로 없음)"을 명시.

### 4.2 JSON 목록 (정밀형) — 확장자 `.json`으로 판별

```json
[{"id": "OwnerController#findOwner", "w": 120, "group": "OwnerController"},
 {"id": "PetController#create", "group": "PetController"}]
```

- 필수 `id`(비어있지 않은 문자열, 중복 금지 — 리터럴 비교). 선택 `w`(양수 숫자;
  생략 시 1.0), 선택 `group`(문자열; 생략 시 무그룹). 그 외 키는 무시(관용 수용).
- 스키마 위반(배열 아님·id 누락/비문자열·w 비양수/비숫자)은 항목 인덱스를 병기한
  한국어 SystemExit. **JSON 구문 오류**도 `load_calibration`의 JSONDecodeError
  처리와 같은 패턴의 한국어 SystemExit이다 (raw traceback 노출 금지).
- 단위 유형 필드는 **의도적으로 없다** — 단위 의미는 사용자만 안다 (§2 계약).
- **stdin(`-`)은 텍스트 목록 전용이다** — 형식 판별이 `.json` 확장자 기반이라
  stdin으로는 JSON을 공급할 수 없다. 조용한 오파싱을 막기 위해 stdin의 첫
  비공백 문자가 `[` 또는 `{`이면 "stdin은 텍스트 목록 전용 — JSON 목록은
  파일로 지정하라"는 한국어 SystemExit을 낸다.

### 4.3 `--n <개수>`

합성 id `unit-<k>` (k는 `len(str(N))` 자리 동적 제로패딩 — N=100이면 `unit-001`…
`unit-100`; 사전식 정렬 = 숫자 순서), 균일 w, 무그룹.

## 5. 내부 표현: 슬라이스 합성 (뒷단 무수정의 핵심)

범용 앞단은 스캐너와 **같은 슬라이스 스키마**를 합성한다:

```python
{"endpoint": {"method": "", "path": id,
              "controller": group if group else f"\x00{id}"},
 "w_tokens": w, "unresolved": [], "external_call": False}
```

- `controller`가 그룹 힌트 그대로 → `plan._controller_groups`의 FFD 묶음이
  무수정으로 group 친화 배치가 된다.
- **무그룹 대상은 항목별 고유 키**(NUL 접두 + id — 사용자 group과 충돌 불가)로
  합성한다. 하나의 "(무그룹)" 버킷으로 묶으면 FFD가 이들을 한 덩어리로 co-pack해
  다른 묶음의 남은 용량을 개별 항목이 채우지 못하는 배치 비효율이 생긴다 —
  고유 키면 각 항목이 독립 그룹으로 자유 배치된다.
- 표시 문자열은 헬퍼 `_display(s)` 하나로 단일화한다:
  `method`가 비면 `path`(=id)만, 아니면 기존 `"{method} {path}"`. 리포트·
  `--groups` 출력·plan.json chunks가 공유한다.

## 6. 공통 이상치 감지 (모든 앞단)

- **판정**: `w > OUTLIER_MEDIAN_MULT × median(w)` (기본 4). N < 4이거나
  median이 0이면 판정하지 않는다. `OUTLIER_MEDIAN_MULT`는 **모듈 레벨 코드
  상수다 — CLI 옵션으로 노출하지 않는다** (검증된 재산정 근거가 없는 값을
  사용자 다이얼로 만들지 않는다; §10).
- **균일 w 경로에서는 정의상 결코 발동하지 않는다** — `--n`, 텍스트 전체/부분
  폴백, JSON 전원 w 생략 경로에서는 w=median이라 항상 거짓. 이질적 크기를
  알리려면 JSON으로 w를 명시해야 한다. 이 사실을 CONCEPTS.md에도 적는다.
- **효과**: 리포트 + stdout에 경고 — 이상치 목록(최대 5건, w와 배수 병기)과
  권고문: "이 대상들은 나머지와 크기가 이질적입니다 — 현재 셀 계수로의 외삽은
  과소추정 위험이 있어 **별도 라벨로 분리 측정**을 권장합니다." 문구에 '파일럿'
  단어를 쓰지 않는다 — `test_pilot_notice.py`가 "`--calibration` 명시 시 stdout에
  '파일럿' 없음"을 불변식으로 검증하고 있고, 이상치 경고는 캘리브레이션 소스와
  무관하게 나온다.
- **stdout 삽입 위치**: `N=…` 요약 줄 직후, `--groups` 블록·파일럿 고지(ℹ)보다
  앞. (파일럿 고지의 "--groups 뒤" 순서 계약은 기존 테스트
  `test_pilot_notice_follows_groups_block`이 지키고 있다 — 건드리지 않는다.)
- **강제 단독 배치는 하지 않는다** (대화에서 언급했던 "단독 그룹 보장"의 정제):
  청크 고정비 a가 중복되어 총비용이 되레 늘 수 있고, δ̂ 기반 FFD가 용량 초과
  항목을 이미 자연 격리한다(`_pack`의 그룹 내부 분할). 감지의 가치는 배치 강제가
  아니라 **모델 적용 한계의 정직한 고지**다.
- Spring 경로에도 동일 적용 → 기존 petclinic 골든 리포트가 바뀔 수 있다.
  구현 시 재생성하고 HANDOFF.md 기준선을 갱신한다.

## 7. 리포트·출력 어휘

단위 명사는 앞단이 결정한다: 스캐너 = "엔드포인트"/"EP", 범용 소스 = "대상".
`대상:` 줄의 소스 라벨: 스캐너 = 프로젝트 경로(기존), `--targets` = 목록 파일 경로
또는 `(stdin, N건)`, `--n` = `(--n N)`.

cli.py의 스캐너 결합 리터럴 전수와 처리 (리뷰 C-I3 — 두 예시로 완결성을
암시하지 않고 전부 열거한다):

| 리터럴 (cli.py) | 스캐너 소스 | 범용 소스 |
|---|---|---|
| `N = {n} 엔드포인트` (241) | 유지 | `N = {n} 대상` |
| `(미해결 슬라이스 …)` (241) | 유지 | 생략 (합성 슬라이스에 unresolved 없음) |
| `## 권장 플랜` 이하 셀·벽·K*·곡선 줄 | 동일 | 동일 (단위 무관) |
| 매트릭스 표·haiku 캐비앗 | 동일 | 동일 |
| `## 컨트롤러 단위` + 인용문 + 표 헤더 `컨트롤러`/`n (EP)` (274-279) | 유지 | `## 그룹 단위`, 헤더 `그룹`/`n` — **명시 group이 하나도 없으면 섹션 전체 생략**; 혼재 시 명시 group 행만 표시(무그룹 항목은 §5의 합성 고유 키라 사용자 어휘가 아니다) |
| `## 슬라이스 크기 상위 10 엔드포인트` + w 각주 + 표 헤더 `Endpoint`/`external`/`unresolved` (284-286) | 유지 | `## w 상위 10 대상`, 표 헤더 `대상`/`w (tokens)` (external/unresolved 열 생략 — 합성 슬라이스에서 항상 공란); **w 균일이면 표 생략**(전부 같아 무의미) + "w: 균일 가정" 한 줄 |
| 한계 고지 `정적 슬라이스는 리플렉션…` (297) | 유지 | 생략 (스캐너 전용 주장) |
| 한계 고지 `w는 코드 크기(bytes/4)…복잡도 미반영` (293) | 유지 | w 출처별 문구: 파일 크기 자동이면 "w는 파일 크기(bytes/4)" / JSON 명시면 "w는 사용자 제공값" / 균일이면 "w 균일 가정" |
| 파일럿 고지(ℹ)의 `EP 1개짜리` (333) | 유지 | `대상 1개짜리` — 단위 명사 헬퍼로 라우팅 |
| `_env_wall_warning`의 `EP당 1청크로 퇴화` (108) | 유지 | `대상당 1청크로 퇴화` — 동일 헬퍼 |
| `--groups` 헤더 `[{project_root.name}]` (305) | 유지 | `[<소스 라벨>]` (§3) — `Path(None)` TypeError 경로 제거 |

그 외 셀 기반 출력(파일럿 고지 본문·매트릭스·예측구간·비용 곡선)은 위 표의 단위
명사 치환을 제외하면 전 소스 동일하다.

## 10. 비범위 (명시적 제외)

- **import-클로저 기반 코드 인지 w** (2차): 1차 실사용에서 크기-only w의 배분
  왜곡 증거가 쌓이면 착수.
- **α(=0.5) 적합 기능**: w 분산 큰 파일럿 확보 후 별도 검토.
- **이상치 기준(4×median)의 데이터 역검증**: 캠페인 데이터는 w 분산이 작아
  (§4.7, R²≈0) 기준 검증에 부적합 — 초깃값 4는 관례적 보수값. 재검토 전까지
  CLI에 노출하지 않는다 (§6).
- 라벨 자동 분리·자동 파일럿 실행 (툴은 권고까지만).
