# N 스케일링 분석 — N=100/200에서 각 암의 비용 패턴은 유지되는가

> 결론 요약: **유지되지 않는다.** flat의 준선형성은 단일 세션이 감당 가능한 N(~수십)
> 까지만 성립하며, 그 너머에서는 컨텍스트 상한·컴팩션·지침 망각이 겹쳐 비용과 품질이
> 동시에 무너진다. N=100+의 올바른 실행 형태는 **청크드 flat**(K개씩 묶은 독립 flat
> 세션 × ⌈N/K⌉회)이며, 이때 총비용은 다시 선형이 된다.
>
> 근거 데이터: `results/run_ledger.jsonl`, run별 트랜스크립트의 턴 단위 컨텍스트 실측.

---

## 1. 실측: N=1 → N=8에서 관찰된 것

### 1.1 run 수준 (3회 중앙값, USD)

| 암 | N=1 | N=8 | 8배 규모의 비용 배수 | 엔드포인트당 단가 |
|---|---|---|---|---|
| flat | 3.39 | 10.21 | **3.0x** (준선형) | $3.39 → **$1.28** (-62%) |
| batched | 6.45 | 18.31 | 2.8x (준선형) | $6.45 → $2.29 |
| per_endpoint | 7.65 | 80.83 | **10.6x** (초선형) | $7.65 → $10.10 (+32%) |

flat·batched의 준선형성 = 고정 오버헤드(환경분석, 지침 적재)의 상각.
per_endpoint의 초선형성 = 스폰 수 ∝ N에 더해, 오케스트레이터 세션 자체가 N에 비례해
길어지며 매 위임마다 점점 커진 컨텍스트를 재읽기 때문.

### 1.2 턴 수준 — flat 세션 내부에서 실제로 일어나는 일

트랜스크립트에서 message.id 단위로 dedup한 턴별 컨텍스트(cache_read+input+cache_write):

| run | 턴 수 | 시작 컨텍스트 | 종료 컨텍스트 | 세션 누적 read |
|---|---|---|---|---|
| flat-n1-r1 | 32 | 51.5K | 140K | 2.9M |
| flat-n8-r3 | 50 | 52.1K | 178K | 6.3M |
| flat-n8-r1 | 83 | 52.4K | **257K** | 13.3M |

두 가지가 동시에 자란다:

- **턴 수 ∝ N** (엔드포인트마다 분석·작성·검증 턴이 필요)
- **턴당 컨텍스트 ∝ 그때까지의 누적 작업량** (도구 결과가 대화에 쌓임)

따라서 세션 총 read 토큰은 대략 `Σ(턴당 컨텍스트)` = **N에 대해 2차(quadratic)** 로
증가한다. N=8까지는 상각 이득이 2차 항을 압도하지만, 2차 항은 반드시 역전한다.

## 2. 비용 모델과 외삽

flat 단일 세션의 비용을 다음처럼 근사한다 (계수는 N=1, N=8 실측 fit):

```
C(N) ≈ a + b·N + c·N²
  a ≈ 고정 오버헤드 (지침 적재 + 환경분석)  ≈ $2.4
  b ≈ 엔드포인트당 한계 작업 (authoring 출력 + 해당 턴 read)  ≈ $0.8
  c ≈ 컨텍스트 누적에 의한 2차 항  ≈ $0.02/EP²
  (N=1: 2.4+0.8+0.02 ≈ $3.2 ✓,  N=8: 2.4+6.4+1.3 ≈ $10.1 ✓)
```

이 모델을 **컨텍스트 벽을 무시하고** 외삽하면:

| N | 단일 세션 flat (모델 외삽) | 청크드 flat (K=8) | per_endpoint (선형 외삽) |
|---|---|---|---|
| 8 | $10.2 (실측) | $10.2 | $80.8 (실측) |
| 32 | $48 | $41 | $323 |
| 100 | **$282** | $128 | $1,010 |
| 200 | **$963** | $255 | $2,021 |

단일 세션 flat은 N≈30 부근에서 청크드 flat에 역전당하고, N=100에서는 2.2배 비싸다.
**그리고 실제로는 이 외삽조차 도달 불가능하다** — 아래의 벽 때문이다.

## 3. 세 개의 벽 (비용 모델보다 먼저 오는 것들)

### 3.1 컨텍스트 윈도우 상한

실측 종료 컨텍스트는 N=8에서 이미 178~257K. 엔드포인트당 컨텍스트 증가분
≈ (257K−52K)/8 ≈ **26K/EP** (최악 run 기준). 외삽:

| 상한 | 도달 N (최악 run 기준) | 도달 N (양호 run 기준 ~16K/EP) |
|---|---|---|
| 200K (표준) | **N ≈ 6** — 이미 아슬아슬 | N ≈ 9 |
| 1M (확장) | N ≈ 36 | N ≈ 59 |

즉 N=100은 1M 확장 컨텍스트로도 단일 세션에 들어가지 않는다. N=8 실측에서 flat이
게이트를 전부 통과한 것은 상한 직전에서 멈췄기 때문이라고 봐야 한다.

### 3.2 컴팩션 = 캐시 무효화 + 정보 손실

상한에 근접하면 Claude Code는 자동 컴팩션(대화 요약·재작성)을 수행한다. 이때:

- **프리픽스가 재작성되므로 그 시점까지 쌓인 캐시가 전부 무효화**된다. 이후 첫 턴은
  전체 컨텍스트를 cache_write(1h 기준 2.0x 단가)로 재적재 — 비용 스파이크.
- 요약 과정에서 **초반 지침(62KB 스티어링)의 세부·프로젝트 컨벤션·이미 처리한
  엔드포인트의 결정 사항**이 손실된다. 이후 산출물의 일관성(네이밍, 베이스 클래스,
  SQL 컨벤션)이 흔들린다.
- 컴팩션은 N이 클수록 여러 번 발생하고, 매회 위 비용을 반복한다.

### 3.3 지침 망각 (컴팩션 이전에도)

컴팩션이 없어도, 컨텍스트가 커질수록 초반 지침의 실효 영향력은 떨어진다(attention
희석). 배칭 검정 문서 §4가 "긴 단일 패스에서 후반 엔드포인트 품질 저하"로 사전
인지했던 리스크와 같은 메커니즘이다. 본 실험 N=8에서도 batched N=8의 게이트 실패
2건(산출물에 스킬 stdout 혼입, 수량 미달)은 모두 **세션 후반부 산출물**에서 발생했다
— N=100 단일 세션에서는 이 비율이 훨씬 커질 것으로 예상해야 한다.

### 정리: 암별 예상 패턴 (N=100/200)

| 암 | N=100/200에서 일어나는 일 |
|---|---|
| flat (단일 세션) | **실행 불가** — 1M 컨텍스트로도 N≈36~59가 한계. 컴팩션 강제 발동 시 비용 스파이크+품질 붕괴 |
| batched | 스테이지 서브에이전트가 N=100을 단일 패스 처리 불가(동일한 벽) → §2-D 청킹 강제 발동, 청크 수 ∝ N → **per_endpoint 방향으로 수렴** |
| per_endpoint | 벽은 없음(스폰이 독립적) — 그러나 단가가 최악($10/EP), N=100이면 ~$1,000 |

## 4. 처방: 청크드 flat (chunked flat)

### 4.1 구조

```
공유 컨텍스트 준비 (1회):
  환경분석·스택 탐지 산출물을 파일로 생성 (.nimbus/artifacts/test-env, dev-stack)
  — batched 암의 [A] 규칙을 flat에 이식

메인 루프 (⌈N/K⌉회, 독립 flat 세션):
  for chunk in chunks(endpoints, K):
      claude -p "<flat 지침 + 공유 산출물 경로 참조 + chunk 엔드포인트 표>"
      # 각 세션은 상한과 무관, 컴팩션 없음, 지침 신선도 유지
      게이트 실패 청크만 개별 재실행
```

- 비용: `C_chunked(N) ≈ ⌈N/K⌉ × C(K)`. K=8 실측값 기준 N=100 ≈ **$128**, N=200 ≈ $255.
  공유 컨텍스트 재사용으로 청크당 고정비 a를 더 줄일 수 있다(a의 상당 부분이 환경분석).
- 품질: 실패의 격리 단위가 청크(8개)로 줄어 재작업 비용이 국소화된다. 지침은 매 세션
  선두에 위치해 망각·컴팩션 리스크가 구조적으로 제거된다.
- 병렬화: 청크 세션은 상호 독립이므로 워크스페이스만 분리하면(git worktree) 벽시계
  시간을 청크 수만큼 단축할 수 있다 — 단 이 경우 세션 간 캐시 공유가 깨져 비용이 다소
  증가하므로(공유 프리픽스가 세션마다 cache_write), 비용 최우선이면 순차, 시간
  최우선이면 병렬을 선택한다.

### 4.2 최적 청크 크기 K

트레이드오프: 고정 오버헤드 상각(∝1/K, K를 키울 유인) vs 2차 항+품질 리스크(∝K,
K를 줄일 유인). 모델상 순수 비용 최적은 `K* = √(a/c) ≈ √(2.4/0.02) ≈ 11`이며,
품질 게이트(후반부 열화)와 컨텍스트 여유를 감안하면 **K=8~12**가 안전 권장 범위다.
실측 확정을 위한 후속 실험: **N=16, 32 스윕** — 엔드포인트당 단가와 게이트 통과율이
꺾이는 지점을 직접 관측하면 K*를 데이터로 고정할 수 있다.

### 4.3 kiro/다른 러너에의 함의

이 분석은 Claude Code 특정 수치(1h 캐시, 컴팩션 동작)에 기반하지만, 구조는 일반적이다:
"단일 세션의 비용은 N에 2차, 상한 벽은 그보다 먼저 온다"는 컨텍스트 누적형 에이전트
전부에 적용된다. kiro로 되돌아가도 처방은 동일하다 — **토폴로지를 바꾸지 말고 작업을
청크로 나눠 flat을 반복하라.**

## 5. 한계

- N=16~200 구간은 실측이 아닌 모델 외삽이다. 계수 fit이 2점(N=1,8)이라 c의 신뢰구간이
  넓다 — N=16/32 스윕이 선행되어야 확정된다.
- 컴팩션 발동 시의 실제 비용 스파이크·품질 저하는 본 실험에서 관측되지 않았다(발동
  전에 세션이 끝났기 때문). 위 서술은 컴팩션 메커니즘(요약·프리픽스 재작성)에서의
  연역이다.
- 청크드 flat의 공유 컨텍스트 재사용 이득은 추정이며, 구현 시 청크 간 산출물 충돌
  (같은 파일을 다른 청크가 수정)을 막는 파일 소유 규약이 필요하다.
