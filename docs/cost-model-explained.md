# 비용 모델 해설 — 왜 2차인가, 왜 청크로 1차를 만드나, K는 왜 중요한가

> kn-estimator([GUIDE](GUIDE.md))의 수학적 토대를 설명한다. 본문 수치는 2026-07
> 캠페인 실측(petclinic flat/sonnet, `../results/campaign/petclinic/`)에서 나왔다.
> (본문이 참조하는 그림 1~3은 원 실험 저장소의 산출물로 이 저장소에는 동봉되지
> 않았다 — 각 그림의 수치는 본문과 부록에 그대로 있다.)

---

## 1. 왜 "2차(quadratic)"인가

**"2차"는 2차 함수(y = x²꼴), quadratic은 그 영어 표현이다.** "엔드포인트 수 N이
커질 때 비용이 N²에 비례해 커진다"는 뜻이다. 선형(1차)과의 차이:

| | 일이 2배가 되면 | 일이 10배가 되면 |
|---|---|---|
| 선형 (비용 ∝ N) | 비용 2배 | 비용 10배 |
| **2차 (비용 ∝ N²)** | **비용 4배** | **비용 100배** |

직관적으로는 "엔드포인트가 2배니 비용도 2배겠지"(선형)라고 기대하게 되지만,
단일 LLM 세션은 그렇게 동작하지 않는다. 이유는 실측 그래프 한 장으로 보인다:

*(그림 1: 턴별 컨텍스트 누적 실측 — 65K에서 시작해 82턴 뒤 285K. 미동봉, 수치는 부록 참조)*

단일 세션에서 엔드포인트를 순서대로 처리하면 두 가지가 **동시에** 자란다:

1. **턴 수 ∝ N** — 엔드포인트마다 분석·작성·확인 턴이 필요하다 (실측 3~4턴/EP,
   petclinic flat/sonnet 기준).
2. **턴 하나의 읽기 비용 ∝ 그때까지 쌓인 컨텍스트** — LLM API는 매 턴 대화 이력
   전체를 다시 읽고(cache_read), 이력에는 앞선 엔드포인트들의 도구 결과가 계속
   잔류한다 (실측 +15K 토큰/EP). 위 그림에서 65K로 시작한 컨텍스트가 82턴 뒤
   285K가 된 것이 그 누적이다.

그래서 i번째 엔드포인트는 "앞의 i−1개가 남긴 짐"을 지고 처리된다. 총 read 비용은
**곡선 아래 면적**이고, 밑변(턴 수)과 높이(컨텍스트)가 둘 다 N에 비례하니 면적은
N²에 비례한다. 수식으로:

```
총 read ≈ Σᵢ τ·(S0 + δ·i)  (i = 1..N)
        = τ·S0·N  +  τ·δ·(1+2+…+N)
        = (1차 항)  +  τ·δ·N(N+1)/2      ← 1+2+…+N ≈ N²/2 이므로 2차 항
```

이를 정리한 것이 비용 함수 `C(N) = a + bN + cN²`이다
(a: 고정비 — 지침 적재·환경분석, b: 엔드포인트당 한계비용, c: 누적 컨텍스트 계수.
petclinic flat×sonnet 실측 합성: a≈3.78, b≈0.38, c≈0.008).

## 2. 왜 2차를 1차로 만드나 — 청크드(chunked) 실행

*(그림 2: 단일 세션 2차 곡선 vs 청크드 계단 — 미동봉, 계수는 부록 참조)*

- **빨간 곡선 (단일 세션)**: C(N) = a + bN + cN². N이 작을 때는 고정비 상각 덕에
  싸 보이지만, cN² 항이 반드시 역전한다 (이 계수 기준 교차점 N≈22). 게다가
  N≳49부터는 컨텍스트 윈도우의 유효 벽(1M×0.9)에 걸려 **실행 자체가 불가능**해진다
  — 비용 문제 이전에 벽 문제다.
- **파란 계단 (청크드 flat)**: 엔드포인트를 K개씩 끊어 **독립 세션**으로 돌리면
  각 세션은 작은 N=K에 머물러 2차 항이 억제되고, 총비용은
  `⌈N/K⌉ × C(K)` — **N에 비례하는 1차 함수**가 된다. 계단 모양은 청크가 하나
  추가될 때마다 C(K)씩 오르기 때문이다.

여기서 흔한 오해 하나를 짚으면: 청크 **내부**도 여전히 2차다. 2차 항이 사라지는 게
아니라, **2차 항이 아직 지배하지 못하는 구간 안에 K를 가둬두는 것**이다. 각 청크는
2차 곡선의 "아직 싼 앞부분"만 잘라 쓰고, 그 조각들을 이어붙인 전체가 직선이 된다.

## 3. K는 왜 중요한가 — 직선의 기울기를 결정한다

청크드 실행이 만드는 1차 직선의 기울기는 **엔드포인트당 단가 g(K) = C(K)/K**다.
이 단가가 K에 대해 U자 곡선을 그린다:

*(그림 3: 단가 g(K) U-커브 — 미동봉, 계수는 부록 참조)*

```
g(K) = C(K)/K = a/K + b + c·K
         ↑고정비 상각          ↑2차 페널티
      (K 키울수록 이득)      (K 키울수록 손해)
```

- **K가 너무 작으면** (곡선 왼쪽): 청크마다 고정비 a(지침 적재·환경분석)를 다시
  낸다. 극단인 K=1이 per_endpoint 토폴로지다 — 위 계수로 g(1)=$4.17/EP vs
  g(K*)=$0.72/EP, **5.8배**. (초기 레거시 실험의 K=1 실측도 7.9배였다.)
- **K가 너무 크면** (곡선 오른쪽): 청크 내부의 2차 항이 커지고, 품질 리스크
  (컴팩션, 후반부 지침 망각 — 실측에서 게이트 실패가 세션 후반부에 몰렸다)가 얹힌다.
- **최적점**: 두 힘이 균형하는 `K* = √(a/c)` ≈ 22 (petclinic flat×sonnet 계수).
  단 이것은 비용만의 최적이고, 실제로는 컨텍스트 벽(K*_wall)과 품질 리스크가 먼저
  묶는다 — 도구는 셀별 캘리브레이션과 W_soft 용량으로 K를 다시 계산하므로 보고서의
  k_avg는 이보다 작다 (예: 동봉 계수·기본 W_soft에서 petclinic k_avg=6.0).

즉 K는 "몇 개씩 묶느냐"라는 사소한 실행 옵션이 아니라, **전체 비용 직선의 기울기와
품질 리스크를 동시에 결정하는 1차 설계 변수**다.

---

## 4. 그래서 kn-estimator가 하는 일

위 수식의 구조는 보편적이지만 **계수 a, b, c는 프로젝트마다 다르다** — 엔드포인트
수, 코드 복잡도, DI 구조, 매퍼 크기에 따라 δ(컨텍스트 잔류)와 τ(턴 수)가 달라지기
때문이다. kn-estimator는 착수 전에:

1. 대상 프로젝트를 **정적 스캔**해 N과 엔드포인트별 작업량 w_i를 계산하고 (§2 그림의
   "곡선 기울기"를 프로젝트에 맞게 보정),
2. 실측 캘리브레이션 계수(S0/τ/δ/out)로 **청크를 턴 단위 시뮬레이션**해 g(K) 곡선을
   그 프로젝트 버전으로 다시 그리고,
3. 비용 최적(K*_cost)과 컨텍스트 벽(K*_wall) 중 먼저 걸리는 제약으로 **청크 플랜**
   (`kn-plan.json`)을 산출한다 — 균일 K가 아니라 컨트롤러 친화 bin-packing이므로
   결과물은 "K 하나"가 아니라 청크별 구성이다.

한 줄 요약: **2차 곡선을 싼 조각으로 잘라 1차 직선을 만들고, 그 직선의 기울기가
최소가 되는 조각 크기를 프로젝트별로 미리 계산한다.**
