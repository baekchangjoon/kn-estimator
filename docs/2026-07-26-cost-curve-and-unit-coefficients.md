# 비용 곡선 계수(a,b,c)와 단위별 계수의 가능성 — 검정 결과와 반영 내역

> 질문: "비용 그래프가 C(N) = a + bN + cN² 형태일 텐데 a,b,c를 구하는 것과,
> 서브패키지·컨트롤러·서비스 단위로 k, n, a, b, c를 구하는 게 가능한가?"
> 답: **전역 a,b,c는 두 방법으로 구해지고 서로 교차 검증된다. n·k의 단위별 산출은
> 즉시 가능하다. 서비스 단위 a,b,c는 실증됐다. 컨트롤러·서브패키지 단위 a,b,c는
> 추정은 가능하나 분화의 유의한 근거가 없다** — 본 문서의 검정이 그 근거다.

## 1. 전역 a, b, c — 두 방법, 교차 검증

**방법 A — 채널 분해 후 합성 (해석적, 정본).** 캘리브레이션의 관측 가능량 7개
(S0, δ_env/δ_ep, τ_env/τ_ep, out_env/out_ep)로 비용식이 닫힌 형태의 2차식이 된다
(`plan.cost_coefficients`, 균일 ŵ=1 기준):

```
a = P_cr·τ_env·(S0+δ_env/2) + P_cw·(S0+δ_env) + P_out·out_env   (청크 고정비)
b = P_cr·τ_ep·(S0+δ_env) + P_cw·δ_ep + P_out·out_ep             (EP 한계비용)
c = P_cr·τ_ep·δ_ep/2                                             (컨텍스트 누적 항)
```

동봉 캘리브레이션(kn-cal-1)의 셀별 값:

| 셀 | a (고정, $) | b ($/EP) | c ($/EP²) | K\*=√(a/c) |
|---|---|---|---|---|
| flat/opus | 2.62 | 0.772 | 0.0230 | 10.7 |
| flat/sonnet | 3.15 | 1.039 | 0.0495 | 8.0 |
| template/opus | 1.36 | 0.413 | 0.0114 | 10.9 |
| template/sonnet | 1.31 | 0.391 | 0.0131 | 10.0 |
| template/haiku | 0.14 | 0.028 | 0.0004 | 18.9 |

**방법 B — 실측 비용 직접 fit.** flat/opus 실측 2점 fit(문서
`cost-model-explained.md`)은 a≈2.4, b≈0.8, c≈0.02 — 방법 A의 합성값
(2.62/0.772/0.0230)과 독립적으로 일치한다.

**제약:** 순수 비용 fit은 미지수 3개에 실측 N이 2종(1, 8)뿐이라 단독으로는
미결정이다. 방법 A(채널 분해가 자유도를 보충)가 정본이며, 3번째 N(예: N=16,
셀당 3 run ≈ $30~60)을 실측하면 c의 독립 검증이 가능해진다.

`cost_coefficients`가 `simulate_chunk`와 수치 일치함은 테스트로 고정돼 있다
(`tests/test_cost_curve_report.py`).

## 2. 단위별 k, n, a, b, c — 항목별 가능성

| 항목 | 가능? | 근거 |
|---|---|---|
| n (단위별 EP 수) | 즉시 가능 | 인벤토리가 EP마다 controller·파일을 가짐. 보고서 "컨트롤러 단위" 표에 반영 |
| k (단위별 배정) | 즉시 가능 | 플랜이 컨트롤러 친화 FFD — 배정 청크를 보고서·kn-plan.json(`controllers`)에 반영 |
| 서비스 단위 a,b,c | 가능 — 실증됨 | 서비스=프로젝트이므로 캠페인 파일럿 재캘리브레이션이 그것 (오차 ±10%). 갈리는 건 주로 a(env 3~4배), b·c는 프로젝트 간에도 안정적(δ_ep ±25%, out_ep ±16%) |
| 컨트롤러·서브패키지 a,b,c | 근거 없음 (아래 검정) | a는 하네스 지배(캠페인 S0 66.1K 동일)라 단위 무관. c(δ_ep)의 단위 분화는 §3 검정에서 기각 |

## 3. 검정 — 컨트롤러 소속이 per-EP 관측의 분산을 설명하는가

**방법** (`research/unit_variance.py`): 캠페인 per-EP 관측 103건
(`results/campaign/analysis/alpha-observations.json`) + SmartPlant template run
6건의 트랜스크립트 복원 관측. run 반복을 EP 중앙값으로 접고 컨트롤러로 그룹핑,
일원 분산분석의 η²(집단간 분산 비율)와 순열검정 p값(10,000회, seed 0).

**결과 (2026-07-26):**

| 프로젝트/채널 | η² | F | 컨트롤러 수 | EP 수 | 순열 p |
|---|---|---|---|---|---|
| petclinic/out | 0.823 | 4.66 | 5 | 9 | 0.079 |
| petclinic/δ | 0.520 | 1.44 | 4 | 8 | 0.341 |
| auth-user/out | 0.153 | 0.18 | 3 | 5 | 0.800 |
| auth-user/δ | 0.628 | 0.84 | 3 | 4 | 0.498 |
| community/out | — | — | 1 | 5 | 검정 불가 (컨트롤러 1개) |
| community/δ | — | — | 1 | 4 | 검정 불가 (컨트롤러 1개) |
| smartplant/out | — | — | 8 | 8 | 검정 불가 (컨트롤러당 EP 1개) |
| smartplant/δ | — | — | 7 | 7 | 검정 불가 (컨트롤러당 EP 1개, 첫 Write는 δ 미정의) |

**해석:**

- **유의한 케이스가 없다** (관례적 α=0.05 기준 전 케이스 p≥0.079). 가장 강한
  신호는 petclinic/out(η²=0.823, p=0.079)인데, MVC 뷰 반환 컨트롤러(VetController,
  out 중앙값 1,980)와 REST 컨트롤러(3,110~3,518)의 차이가 주도한다 — 이는
  "복잡도"가 아니라 산출물 종류의 차이이고, 표본(EP 9개)이 작아 우연과 구분되지
  않는다.
- **절반은 구조적으로 검정 불가다.** community는 컨트롤러가 1개, SmartPlant는
  컨트롤러당 EP가 1개다 — 이런 구조에서는 단위별 계수가 원리적으로 식별 불가능하다
  (단위간 차이와 EP간 차이를 분리할 수 없다).
- §4.7(overview)의 w 공변량 검정(δ⊥w, R²=0.000)과 방향이 일치한다: EP별·단위별
  차이는 run 간 분산(±11~21%)에 묻힌다.

**결론: 컨트롤러·서브패키지 단위의 a,b,c 분화는 만들지 않는다.** 전역(셀) 계수를
유지하고, 단위 수준에서는 n·Σw·배정 청크만 산출한다. 이 결정을 뒤집으려면 컨트롤러
수·컨트롤러당 EP 수가 모두 큰 프로젝트에서 단위 순수 청크 실측이 필요하다.

## 4. 도구에 반영된 것 (2026-07-26)

- **보고서(kn-report.md)**: 권장 플랜에 비용 곡선 라인
  `C(K) ≈ a + b·K + c·K² (a: 청크 고정비, b: EP 한계비용, c: 컨텍스트 누적 항)` 병기,
  "컨트롤러 단위" 표(컨트롤러·n·Σw·배정 청크) + 전역 계수 유지 사유 고지.
- **kn-plan.json**: `cost_curve` {a,b,c}, `controllers` {이름: {n, w_tokens, chunks}}.
- **plan.py**: `cost_coefficients()` 신설, `k_stars()`가 이를 재사용 (닫힌 형태 단일화).
